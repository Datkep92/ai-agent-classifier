UPDATE 2026-10-05 23:21:21 --- COMPLETION AUDIT AND GAP FIXES
Status: PASS

1. AUDIT FOUND (and now fixed) REAL GAPS
- a) ui/ held a STALE DUPLICATE of the UI whose imports (../core/)
  were wrong for a root deploy. Two drifting copies of the same file
  is a real maintenance hazard. Removed ui/; root files are the only
  source of truth. Server aliases for /ui/* removed to match.
- b) Auto-recovery (plan 19) was DEAD CODE. isRecoverable(),
  needsManualRecheck() and refreshBreaker() existed but nothing ever
  called them, so an expired cooldown never actually freed a mapping
  and an elapsed circuit never moved to HALF_OPEN.
  Now wired into Router.candidates(), which every path (pick, UI,
  test engine) goes through.
- c) HALF_OPEN had no probe budget. config.circuit.halfOpenProbes was
  configured but unused, so a recovering provider could be stampeded.
  The budget is now claimed before a real request and enforced during
  candidate selection.
- d) Event log grew without bound (plan 31). CONFIG.eventLogLimit was
  defined but never applied. Registry now trims to the cap on write.
- e) TEST KEY / TEST MODEL / Retry were unreachable from the UI
  (plan 20, 22). Added: per-key TEST button, per-mapping retry,
  Retry-failed and Re-test-healthy filters. No dead handlers remain.
- f) testAll() silently skipped orphaned mappings, hiding data
  integrity problems. They are now counted and surfaced.

2. BUGS FOUND BY THE NEW TESTS
- recover() lived only in pick(), so callers of candidates() saw stale
  cooldowns. Moved into candidates(); test R1 covers this.
- Retention, concurrency, filter and cancel paths had no coverage at
  all before; tests O1-O5 now pin them down.

UPDATE 2026-10-05 23:32:46 --- KEY AUTO-MAP FIX + VIETNAMESE UI
Status: PASS

1. BUG REPORTED AND FIXED
Symptom: pasting a key produced no tree at all. The key stayed in
Unresolved and never appeared under the provider.

Root cause: resolveUnresolved() only handled MODEL items. Every
API_KEY item hit an early `kept.push(item); continue;` and was never
retried, so a key pasted before its provider could never bind to it.

Fixes in core/mapper.js:
- API_KEY items are now scanned against every known provider.
- A cheap discovery call authenticates the key before any inference
  request is spent.
- A key rejected by one provider is retried against the next instead of
  being declared dead, because AUTH_INVALID is only valid for that
  provider.
- A key that authenticates but advertises no models is still attached
  to the provider (AUTH_OK_NO_MODELS) so it is visible in the tree.
- A model that no provider advertises is now probed directly instead of
  being discarded: not being listed is not proof of being unusable.
  Only a real inference PASS resolves it.
- Unresolved items updated during resolution are now persisted. Before
  this, the UI kept rendering the original parked hint, so the inbox
  showed "OpenCode" forever instead of the actual verdict.

2. VIETNAMESE UI
- index.html: all labels, buttons, headings and the banner.
- app.js: status names, item types, pipeline stage names, Unresolved
  reasons, all toasts, log lines and tooltips.
- The core still emits English enum values because they are exported
  and machine-readable; only display text is translated.
